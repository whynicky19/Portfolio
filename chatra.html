The problem

Classrooms run on Telegram chats and spreadsheets.

At my university, educators had no unified tool. Assignments were sent as messages. Attendance was tracked in notebooks. Grades lived in disconnected Excel files. Students had no visibility into their own progress.

The goal: build a platform where teachers create classes, post assignments, track attendance, and publish grades — and where students access all of it from a single app.

Classes

Join a class. See your schedule. Stay on track.

Teachers create classes and post assignments with deadlines. Students join with a code and instantly see everything — lectures, tasks, attendance. No Telegram, no spreadsheets.

Architecture

Three independent layers. One coherent product.

Every layer designed to be independently deployable, tightly integrated via a shared REST API.

Flutter Mobile

Riverpod state · GoRouter navigation · Dio HTTP client · SharedPreferences token persistence · ngrok tunneling for iOS simulator.

FastAPI Backend

JWT authentication · PostgreSQL with SQLAlchemy ORM · Docker containerisation · auto-generated Swagger docs · role-based access control.

Nuxt.js Dashboard

Kazakh & Russian i18n · role-based UI (teacher / student / admin) · real-time grade updates via REST polling.

Subjects

Every subject, organized in one place.

Materials, assignments, and grades are grouped by subject instead of buried in a chat feed. Students open a subject and see exactly what's due, what's graded, and what's next.

Things learned the hard way

Reflection

The hard parts were the valuable parts.

iOS simulator networking with a local FastAPI server required a tunneling setup with ngrok — something no tutorial covered. I figured it out from first principles.

Designing a role-based system (student, teacher, admin) across three platforms meant every API endpoint and every UI screen had to account for permission states. It forced me to think about product architecture, not just code.

Shipping to real users — even a small group — changes how you build. You stop writing code for yourself and start writing it for people who will break your assumptions in ways you never anticipated.
