An educational platform for classes, assignments, attendance, grades, and AI-supported learning — now used in university classrooms.

Context and contribution

A classroom system, built end to end.

Chatra was built by two developers to replace fragmented classroom workflows with one connected mobile, web, and backend system. My work focused on the mobile product, product interface, and integration across the stack.

Key decisions

One product, not three disconnected interfaces.

  1. 01

    Share the system, adapt the surface.

    Mobile and web clients use one REST API while keeping student, teacher, and administrator tasks specific to each role.

  2. 02

    Keep learning context together.

    Schedules, subjects, assignments, attendance, and grades live beside each other instead of being split across chats and spreadsheets.

  3. 03

    Put AI inside the learning flow.

    The assistant sits beside course material in the same product, reducing the need for another account or disconnected tool.

One app. Every class. Every student.

Teachers create classes. Students join with a code. Assignments, attendance, grades, and AI tutoring — all in one place, across three platforms.

Join a class. See your week. Stay on track.

A shared schedule for every subject. Deadlines, attendance, and announcements live next to each other instead of buried in chat threads.

  • One-tap join with a class code
  • Live schedule synced to the server
  • Notifications that respect your time

Every subject, in one place.

Materials, assignments, and grades are grouped by subject — not buried in a feed. Open a subject and see exactly what's due, what's graded, and what's next.

Learning doesn't stop after class.

Ask anything about your material. Get an explanation in seconds. The assistant is built into the same app — no extra download, no separate account.

Bright by day. Easy on the eyes at night.

Every screen, every component, every interaction — designed for light and dark from the first sketch, not retrofitted later.

Three independent layers. One coherent product.

Every layer designed to deploy on its own, tightly integrated through a single REST API.

  1. 01

    Flutter

    Riverpod state, GoRouter navigation, Dio HTTP, secure token persistence.

  2. 02

    FastAPI

    JWT auth, role-based access, automatic Swagger docs, PostgreSQL via SQLAlchemy.

  3. 03

    PostgreSQL

    Classes, users, grades, attendance — normalized once, queried forever.

  4. 04

    Nuxt.js

    Teacher and admin views in Kazakh and Russian. The same API, a different surface.
