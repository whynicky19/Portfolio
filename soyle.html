Overview

Two audiences. One calm family experience.

The problem

Child practice and parent decisions need different levels of detail, control, and language.

The product

Short practice, AAC communication, goals, observations, and a reviewable history.

My contribution

Product design and full-stack implementation across the family experience.

The trust boundary

The planner is deterministic and local; the product does not present generative output as clinical intelligence.

The product problem

Home practice needed less friction—and more trust.

A child needs a short, focused interaction. A parent needs goals, history, and context. Söyle separates those responsibilities while keeping them connected inside one family experience.

01

Design for two very different users.

Child-facing practice minimizes decisions and distractions. Adult views make goals, observations, and progress easier to review.

02

Explain what happens next.

The planner selects the next exercise using visible local rules based on recent results, level, and rotation—not a hidden generative model.

03

Treat privacy as interface design.

Camera use stays in the browser and begins with consent. The UI makes sensitive actions deliberate instead of silently normalizing them.

Experience architecture

Practice for the child. Context for the adult.

The product includes short practice sessions, an AAC phrase builder, parent-defined goals, observations, and a reviewable history. Each part has a clear audience and a clear reason to exist.

Adaptation can be useful without pretending to be intelligent.

The repository documents deterministic planning over the latest eight results, three levels, and rotation rules. That makes the next step inspectable.

Implementation

A typed interface with a small, testable core.

Next.js and React provide the browser experience, while a FastAPI service handles application data. TypeScript keeps the UI contracts explicit. Playwright and axe checks are part of the repository, supporting keyboard and accessibility work as the product evolves.
