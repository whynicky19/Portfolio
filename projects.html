01 / Web + mobile

Chatra

One classroom. Connected everywhere.

A learning platform connecting students, teachers and administrators around the daily work of a class. Classrooms, assignments, messages, calendars and study tools share one role-aware system. The Nuxt web interface and Flutter client connect to the same FastAPI service, keeping authentication and learning workflows consistent across devices. My focus spans the frontend, product interface and integration: making a broad set of tools understandable without losing the context of the classroom.

02 / Web platform

Söyle

Practice for children. Context for parents.

A family practice platform that separates a child's focused activities from the decisions a parent needs to make. Short exercises, AAC communication, goals, observations and history live in a shared experience. The next-step planner uses inspectable local rules rather than generative advice. I worked on product design and full-stack implementation, including role-separated flows and accessible interactions. The working product is presented for further validation, not as a clinically validated service.

04 / Mobile prototype

FreelanceOS

A clearer view of freelance money.

A mobile product concept exploring how freelancers can separate income from money that is actually available to spend. The prototype brings tax reserves, expenses, project payments and financial summaries into a compact dashboard. Its focus is the relationship between those numbers: helping someone understand the state of their work without moving between disconnected views. This is an interface prototype, not a released finance application; no production backend or payment integration is claimed.

05 / Web application

RugPull Risk

Make the risk signals easier to read.

A token-scanning interface that brings contract, on-chain, social and holder signals into one decision workspace. Instead of presenting disconnected data, the responsive frontend organizes the available risk information around a token. The project has separate frontend and backend repositories, reflecting the boundary between collecting signals and presenting them clearly. The portfolio shows the actual scanner interface; its risk indicators are not a guarantee of safety or investment advice.

08 / Backend system

Chatra API

The service behind the classroom.

The FastAPI service connects Chatra's web and mobile clients to shared classroom data. Authentication and roles define access to classes, assignments, files, messaging and moderation workflows. PostgreSQL provides persistence, while documented API routes make the client-facing contract visible. This is the infrastructure side of the same learning product: the work that lets different interfaces share a consistent model of the classroom instead of maintaining disconnected copies of it.

  • Python
  • FastAPI
  • PostgreSQL

09 / Mobile application

Chatra mobile

The same classroom, within reach.

A Flutter client for Chatra's authentication, classroom, messaging and learning workflows. It shares the product's service layer while adapting the interface to a narrow, touch-first screen. Subjects and classes become focused vertical lists, with persistent navigation and familiar classroom concepts. Provider and Dio support client state and data access. The mobile work is shown separately here so the platform-specific interface can be explored alongside the broader web and API system.
