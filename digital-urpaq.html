Overview

Public discovery with a path into action.

The problem

Programmes can be difficult to discover, compare, and follow once an application moves behind authentication.

The direction

Connect the public catalogue to role-aware service views without making them feel like separate products.

My contribution

Full-stack team implementation during a competition build, with a primary focus on the product flow.

The constraint

A short build cycle required careful scope decisions and a clear distinction between the concept and production readiness.

The product problem

One service had to make sense to four audiences.

Visitors need to discover opportunities. Students need applications, schedules, and materials. Teachers need their own working view, while administrators need oversight. The challenge was one coherent system without flattening those different jobs.

01

Start with public discovery.

Programme and circle catalogues, search, and news create a useful path before authentication becomes necessary.

02

Change tools when the role changes.

Student, teacher, and administrator dashboards preserve shared patterns while foregrounding role-specific tasks.

03

Keep the service state visible.

Applications, schedules, and learning materials need clear status and predictable navigation so users can see what happened and what comes next.

Interface system

From catalogue to dashboard without losing the thread.

The product direction connects a public information layer with authenticated service flows. Nuxt layouts, reusable components, Pinia stores, and Tailwind utilities provide the current implementation base.

The public site and operational dashboards belong to one journey.

Shared navigation, spacing, status language, and reusable UI keep the service recognizable as users move from browsing to action.

Implementation

A focused Nuxt and FastAPI competition build.

The implementation uses Nuxt and Vue for the client, Pinia for shared state, Tailwind CSS for the visual layer, and TypeScript for safer contracts. The current repository establishes authentication, catalogue state, and the service foundation; the wider workflow remains a product direction rather than a production claim.
