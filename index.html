What I do

I treat interface design as the work, not the wrapping.

Design comes first. Every screen has a reason to exist, a hierarchy that holds up at a glance, and motion that means something.

Engineering follows — Swift and SwiftUI turned into the same interface, pixel-honest, with the performance and accessibility users expect from native iOS.

Apple Human Interface Guidelines

Good iOS work speaks the platform's language.

I design against HIG because that's what makes an interface feel native — not because it's a checklist, but because each principle solves a real problem.

Hierarchy & clarity

Every element earns its visual weight. Type, color, and spacing carry the meaning so users don't have to think.

Deference

Content first. Chrome quiet. The interface steps back so the work speaks.

Consistency

Same gesture, same outcome — across screens, across the system, every time.

Depth

Translucency, motion, layering — a sense of place and order the eye reads in milliseconds.

Feedback

Every touch acknowledged on press. Every state change visible. The interface never lies about what's happening.

Accessibility

Dynamic Type, VoiceOver, color contrast, Reduce Motion — built in from the first sketch, not bolted on.
