01

System-wide issues

These aren't confined to one page — they're decisions (or non-decisions) that repeat across all six files, which is exactly why they read as systemic rather than incidental.

Criticalstyle.css:4–5 · every <head>

SF Pro is referenced, never shipped — most visitors read Arial.

Why it doesn't feel like Apple: the entire typographic identity of the site rests on -apple-system, "SF Pro Display", "Helvetica Neue", Arial. -apple-system only resolves to SF Pro inside Safari/WebKit on Apple hardware. Everywhere else — Chrome or Edge on Windows, Android, Linux, even Chrome on macOS in some configurations — there is no font literally named "SF Pro Display" installed, "Helvetica Neue" doesn't exist on Windows or Android either, and the stack quietly bottoms out at Arial. Apple.com never takes this risk: it self-hosts SF Pro as @font-face woff2 files specifically so non-Apple visitors still see SF Pro.

How Apple solves it
Self-host the display and text weights as @font-face, with the system stack only as the very first, fastest-resolving candidate — not the whole strategy.
Fix
@font-face{
  font-family:"SF Pro Display";
  src:url("/fonts/sf-pro-display.woff2") format("woff2");
  font-weight:400 700; font-display:swap;
}
/* keep -apple-system first for zero-latency on Apple devices,
   but the named face now actually exists for everyone else */
Important6 files, 6 different gradients

Every page invents its own rainbow "highlight word" — there is no house accent.

Why it doesn't feel like Apple: a real Apple product page uses one signature gradient per product story, repeated consistently everywhere that story appears. Here, every page's .hl-word / .shipped-word gets its own two-stop gradient with no relationship to the others:

index.html

about.html

Fix
Pick one gradient token, put it in :root, use it everywhere a highlight word appears. If a page needs its own identity color, make it a solid --accent swap, not a new gradient invention.
Important12+ one-off max-width values

There is no grid system — there's a max-width picked per component.

Why it doesn't feel like Apple: "perfect alignment" is on your own list for a reason — it's the thing that reads as intentional versus improvised. This codebase defines --max-w:1200px as its one system token, then overrides it ad hoc everywhere: 960px (cs-overview-inner), 1100px (cs-container-wide), 900px (contact-grid), 820px (cs-hero-inner), 760px (cs-container), 700px (about timeline), 680px (qa-list), 560px/540px/520px/500px (assorted hero subcopy), 480px (contact-split), 420px/400px/380px (assorted CTA copy). None of these trace back to a shared token.

Fix
Collapse to three tokens — --w-read: 680px (prose), --w-content: 1200px (page container, already exists), --w-wide: 1440px (full-bleed) — and rewrite every inline max-width to reference one of the three.
Importantapp.js:71–86 · style.css:484–535

One motion recipe — fade up 36px on 8% visibility — is applied to almost everything.

Why it doesn't feel like Apple: hero stat numbers, timeline entries, stack cards, certificate headers, section titles, and CTA copy all share the exact same IntersectionObserver trigger (threshold:0.08) and the exact same opacity 0 → 1, translateY(36px) → 0 transform. It's a switch, not a scrub. Apple's actual signature is progress-linked motion: transform values computed continuously from scroll position, reversible, and specific to what's moving (a phone tilts, a chip data-flows, a title's opacity binds to a percentage — not a boolean). This codebase does exactly that in exactly two places — the word-reveal effect and [data-scroll-scale] — and everywhere else falls back to the one generic reveal.

Fix
Reserve the binary fade-up for genuinely secondary content (footer links, chip rows). Anything positioned as a hero moment — stat counters, the phone mockups, section title reveals — should read scroll progress the way ssEls already does for [data-scroll-scale], not just cross an 8% threshold once.
02

Header & navigation

Criticalstyle.css:418–424

.btn-ghost's hover state is dead — nothing changes when you hover it.

Location: every "About Me" / "See my work" / secondary CTA button sitewide.

Why it doesn't feel like Apple: a microinteraction that silently does nothing is worse than none at all, because a cursor pointer promises feedback the UI doesn't deliver. Trace the cascade: base rule sets background: var(--overlay-md). Generic .btn:hover{opacity:.75} fires first. Then .btn-ghost:hover{opacity:1; background:var(--overlay-md)} — the identical variable — fires second and wins on specificity, restoring opacity to 1 and leaving the background exactly where it started. Net visible change on hover: none.

Current
.btn-ghost { background: var(--overlay-md); }
.btn-ghost:hover { opacity: 1; background: var(--overlay-md); }
Fix
.btn-ghost:hover {
  opacity: 1;
  background: var(--border-hover); /* a token one step darker than overlay-md */
  border-color: var(--border-strong);
}
Importantstyle.css:307–347

The mobile menu is a generic full-screen takeover, not Apple's compact pattern.

Why it doesn't feel like Apple: 24px bold links stacked full-bleed with a staggered navLinkIn entrance per row is the default hamburger-menu gesture of every Webflow/Framer portfolio template — it is not what apple.com does on mobile, where the nav stays compact and list rows are closer to 17–19px with tighter vertical rhythm, not treated as a second hero.

Fix
Drop link size to 19–20px, tighten padding:18px 0 to 14px, and remove the per-row staggered animation-delay chain — Apple's mobile nav appears, it doesn't perform.
03

Hero

Optionalindex.html:103–123

.hero-announce is fully built and never used.

Why it doesn't feel like Apple: a pill-badge component — background, border, dark-mode override, hover state, ~20 lines — exists solely in the <style> block with zero matching element anywhere in index.html's body. Apple ships nothing it didn't finish; leftover scaffolding like this is the tell of a draft that got abandoned mid-iteration, not cleaned up.

Fix
Delete it, or finish it and put it in the hero eyebrow slot it was clearly built for.
Optionalindex.html:418–420

"Available for opportunities" reads as job-seeker convention, not product-hero convention.

Why it doesn't feel like Apple: Apple heroes state what the thing is. A personal-availability status line is a LinkedIn-banner habit, not a product-story habit — worth keeping for the recruiter audience, but it's the first thing that signals "portfolio template" rather than "authored page."

Optionalindex.html:54–115 inline animation-delay

Hero entrance timing is hardcoded to seconds, not tied to actual readiness.

Why it doesn't feel like Apple: .hero-name fires at .2s, .hero-role at .4s, actions at .6s, the scroll cue at 1.4s — a fixed choreography that assumes CSS and fonts are ready by then. Given the SF Pro gap above, on a slow connection the fallback font can still be swapping in mid-animation, which desyncs the whole sequence from what's actually painted.

Fix
Gate the entrance class on a real signal — document.fonts.ready or a load listener — the way the scroll-triggered sections already do via IntersectionObserver, instead of a blind timer.
04

Project cards

Criticalprojects.html:204, 226, 324

~1.9MB of "vector" mockup art loads as static, eager images on one page.

Why it doesn't feel like Apple: img/macbook-card.svg is 668KB and img/crypto-macbook-card.svg is 624KB — for an .svg, that means it isn't clean vector markup, it's raster data wrapped in an SVG shell, carrying all the weight of a PNG with none of the caching/compression benefit browsers give real bitmap formats. The crypto file loads twice on the same page (Hackathon MVP section and again in Practice work). Apple product pages hold themselves to sub-200KB hero imagery per breakpoint, srcset-served.

Fix
Re-export as actual optimized vector paths, or convert to AVIF/WebP at the real display size. Reuse the single crypto-macbook asset via one cached reference rather than two independent requests.
Importantprojects.html:125–135

A filter-tab UI is fully styled in CSS and never appears in the page.

Why it doesn't feel like Apple: .filter-tabs, .filter-tab, .filter-tab.active, and the hover/active states are all defined — pill shape, dark background on active, border transitions — but there is no <div class="filter-tabs"> anywhere in the document. The page presents "Chatra / Portfolio / Hackathon MVP" as flat sequential sections with no way to filter, despite the UI clearly having been designed to support it. This is the second instance (after .hero-announce) of a fully-styled, never-wired feature — a pattern, not a one-off.

Fix
Either wire real filtering (category chips that show/hide .proj-mini and the three featured sections by a data-category attribute), or delete the dead CSS.
Optionalstyle.css vs. experience.html vs. chatra.html

Three card components, three different hover physics, same affordance.

Why it doesn't feel like Apple: .proj-mini:hover changes only border-color and box-shadow (no movement). .ach-card:hover (Experience page) scales to 1.02. .cs-stack-card:hover (Chatra page) lifts translateY(-2px). All three are "here's a card, it's not clickable-but-feels-clickable" — Apple keeps one hover physics per affordance class sitewide.

05

About & skills

Importantabout.html skill-pill icons · contact.html social icons

Skill and social icons are fetched live from a third-party CDN with no fallback.

Why it doesn't feel like Apple: every icon in the skills grid and the contact social row is <img src="https://cdn.simpleicons.org/…"> — eight separate cross-origin requests on About alone. Apple never depends on a runtime third party for iconography; if that subdomain is slow, rate-limited, or blocked by an ad-blocker (icon-serving CDNs are a common blocklist pattern), the skills grid silently renders blank squares where the Python/Flutter/React marks should be.

Fix
Vendor the ~15 icons actually used as local SVGs. It's a one-time download, removes eight round trips, and removes the failure mode entirely.
Optionalabout.html cert-hl-track

The certificate carousel has no desktop affordance beyond tiny dots.

Why it doesn't feel like Apple: drag-to-scroll plus 6px dots works for touch, but a mouse user gets no arrow control and no visual hint that the row scrolls at all until they happen to drag it — Apple's own carousels (e.g. App Store "Today" cards) always pair drag with a visible, clickable arrow.

06

Footer

Criticalall 6 footers

The Chatra link exists in exactly one of six footers.

Why it doesn't feel like Apple: index.html's footer "Portfolio" column lists all six pages including Chatra. about.html, projects.html, chatra.html, experience.html, and contact.html all list only five — Chatra is silently missing from every one of them. Confirmed by grepping every footer block: href="chatra.html" occurs once across the entire site's footers, href="about.html" occurs six times. This is what happens when a shared partial doesn't exist and six independent HTML files are hand/AI-copied with a stray edit in only one — global navigation should never depend on which page you happened to start from.

Fix
Add <a href="chatra.html">Chatra</a> to the other five footers, and treat the header/footer markup as a single source of truth from here — even a client-side include or a tiny build step prevents this class of bug outright.
Optionalall 6 <head> blocks, line ~12

Every page shares one Open Graph image.

Why it doesn't feel like Apple: og:image is chatraweb.jpg on the homepage, About, Projects, Chatra, Experience, and Contact — six distinct pages, one social preview. A link to the Contact page and a link to the Chatra case study render identically in a shared preview card.

07

Mobile

Breakpoints are consistent (900 / 768 / 700 / 600) and the sticky feature grid correctly drops its sticky visual column below 900px rather than breaking. The two real issues are covered above: the full-screen nav takeover (§ Header) and no responsive image sizing at all (§ Performance) — on mobile data, every image ships its full desktop weight.

08

Performance

Importantapp.js:163 · index.html:511

The global lazy-load loop overrides the one image marked high-priority.

Why it doesn't feel like Apple: index.html:511 deliberately marks the Chatra app image fetchpriority="high" decoding="async" with no loading attribute — a real attempt at LCP tuning. But app.js:163 runs document.querySelectorAll('img').forEach(img => { if (!img.loading) img.loading = 'lazy' }) globally, on every image with no exclusion list. Since that image never had loading set, the script stamps it loading="lazy" after the fact — directly contradicting the priority hint sitting right next to it in the markup.

Fix
if (!img.loading && img.getAttribute('fetchpriority') !== 'high') img.loading = 'lazy';
Importantentire codebase

Zero srcset/sizes anywhere — every image ships one resolution to every screen.

Why it doesn't feel like Apple: Apple serves a phone-width visitor a phone-width image. Here, a certificate photo or the Chatra dashboard screenshot ships the same byte count to a 390px iPhone viewport and a 2560px desktop monitor — there is no srcset in any of the six HTML files.

09

Accessibility

Importantchatra.html:385–434 — no matching query

Chatra's page-specific animations ignore prefers-reduced-motion.

Why it doesn't feel like Apple: style.css:880–893 has a genuinely thorough reduced-motion block covering the shared fade/slide/stagger utilities. But Chatra's own <style> block defines three separate phone-reveal keyframes (phoneReveal1/2/3, including an 12px-blur zoom-in) and the word-by-word .tagline-word blur-in, none of which are referenced by that shared query — a vestibular-sensitive visitor with the OS setting on still gets the full blur/scale/translate sequence on this page specifically.

Fix
Add the same @media (prefers-reduced-motion: reduce) guard inside chatra.html's own style block, disabling .tagline-word and the three phoneReveal animations.
Optionalstyle.css:232

Text-selection highlight has no dark-mode value.

Why it doesn't feel like Apple: ::selection{background:rgba(0,0,0,.12)} is defined once, with no [data-theme="dark"] override — a black-tinted highlight at 12% opacity is nearly invisible against the dark palette's near-black background.

Fix
[data-theme="dark"] ::selection{ background: rgba(255,255,255,.16); }
10

Things that immediately reveal this was made by AI

Not a moral judgment — a pattern-recognition exercise. These are the specific fingerprints, cited against the code, not a general impression.

01

A fresh gradient invented per page instead of one reused system

Six pages, six unrelated two/three-stop gradients for the exact same "highlight word" role. A single author building a design system reaches for the same token six times; six independent generation passes each invent their own.

02

Fully-styled UI with nothing wired to it — twice

.hero-announce on the homepage and .filter-tabs on Projects are both complete, production-quality CSS components with zero corresponding markup. Both read as a feature that got scaffolded in one generation pass and abandoned when the prompt moved on, with nothing pruned afterward.

03

The same effect, built twice, two different ways

Word-by-word reveal exists as a real scroll-linked opacity system in app.js (lines 165–196) and as a separate fixed-delay CSS keyframe stagger written inline inside chatra.html (lines 780–828). One codebase, one visual idea, two independent implementations — a sign each was generated fresh rather than reused.

04

Six copy-pasted documents standing in for a template

There's no include system — the <nav>, mobile menu, and <footer> markup is duplicated byte-for-byte across all six HTML files. That's exactly why the footer's Chatra link could silently diverge in five of six copies without anyone noticing — a shared partial makes that class of bug structurally impossible.

05

The same headline cadence on every page

"Student. Builder. Competitor." / "Selected work." / "Let's build something." / "Experience & Activities." — a two-or-three-word declarative fragment, one gradient-highlighted word, one supporting sentence underneath. It's a recognizable generator cadence, not six distinct editorial voices.

06

One easing curve, pasted everywhere

cubic-bezier(.16,1,.3,1) and its sibling cubic-bezier(.23,1,.32,1) — genuinely Apple's own curves — appear on roughly 40 separate transition declarations across the stylesheet. Apple uses a small, curated set of eases tied to what's moving; applying the same one everywhere is the tell of a find-and-replace default, not a motion decision made per element.

11

Redesign plan

Not a rebuild — the structural bones (grid, dark mode tokens, IntersectionObserver reveal system, nav blur values) are closer to Apple's real implementation than most portfolios get. The gap is entirely in the details above. Sequenced by what actually moves the score.

Phase 1 — Fix what's broken, not just imperfect

  • Ship SF Pro as a real font file. Everything downstream of typography — letter-spacing, weight contrast, the entire "premium" read — depends on this one fix landing first.
  • Fix the .btn-ghost hover no-op. A dead microinteraction on every secondary CTA sitewide is a one-line fix with outsized visible impact.
  • Restore the Chatra footer link on the five pages missing it, and extract nav/footer into one shared source so this can't silently re-diverge.
  • Re-export or replace the two 600KB+ "SVG" mockups on Projects. Single biggest performance lever on the site.

Phase 2 — Make the system actually a system

  • Collapse six gradients into one accent token. Reuse it; stop inventing a new one per page.
  • Collapse a dozen max-widths into three tokens (--w-read, --w-content, --w-wide) and rewrite every component to reference one.
  • Either finish or delete .hero-announce and .filter-tabs. Both directions are fine; leaving fully-styled dead code in place is not.
  • Vendor the icon set locally instead of depending on cdn.simpleicons.org at runtime.

Phase 3 — Motion and polish

  • Promote 2–3 hero moments to scroll-scrubbed motion (stat counters, phone mockups) instead of the universal binary fade-up.
  • Unify card hover physics — one lift value, one shadow curve, applied to .proj-mini, .ach-card, and .cs-stack-card alike.
  • Add responsive srcset to every content photograph; stop shipping desktop-resolution images to phones.
  • Extend the reduced-motion query into chatra.html's page-specific keyframes.
